    Остаток

    Мобильный справочник товаров и складских остатков. Учебный проект по дисциплине «Разработка мобильных приложений», 5 семестр.

    О приложении

    Продавцу в магазине постоянно задают вопрос «а это есть?». Остатки обычно смотрят в учётной программе на компьютере, и чтобы ответить, приходится уходить из зала или звонить на склад. «Остаток» решает эту задачу с телефона: находишь товар по названию, открываешь карточку и видишь, сколько штук осталось на складе. Позиции, которые заканчиваются, выделены отдельно, их можно сразу отметить для дозаказа.

    • Тематика: справочник товаров и остатков склада
    • Аудитория: продавцы-консультанты и товароведы небольших магазинов
    • Источник данных: открытый API DummyJSON, раздел products (с Sprint 4)

    Основной сценарий

    1. Покупатель спрашивает о товаре.
    2. Продавец открывает приложение и вводит часть названия.
    3. Находит товар в списке и открывает карточку.
    4. Видит остаток, артикул и статус: в наличии или заканчивается.
    5. Если товара мало, отмечает его для дозаказа.

    Первая версия (MVP)

    • список товаров: название, категория, остаток, картинка
    • поиск по названию
    • фильтр по категории и «только заканчивающиеся»
    • карточка товара
    • отметка товаров для дозаказа и счётчик отмеченных

    Изменять остатки в первой версии нельзя, приложение работает только на просмотр.

    Подробное описание продукта лежит в docs/product-concept.md, пользовательские истории в docs/backlog.md, история изменений в CHANGELOG.md, ретроспектива спринтов в docs/retro.md. Контракт API и команды curl — в docs/api.md, протокол сетевых проверок и разбор логов — в docs/network-checks.md, карта экранов, схема данных и проверки навигации — в docs/navigation.md.

    Запуск

    Нужны Node.js LTS и приложение Expo Go на телефоне. Телефону нужен интернет: товары загружаются с https://dummyjson.com.

    npm install
    npx expo start

    В терминале появится QR-код. На Android его нужно отсканировать в Expo Go, на iPhone — камерой. Телефон и компьютер должны быть в одной Wi-Fi сети. Если не подключается, можно запустить через туннель: npx expo start --tunnel.

    Типы маршрутов (typed routes) генерируются при запуске npx expo start в папку .expo/types. Поэтому после первого клонирования проекта сначала один раз запустить npx expo start, а потом npm run typecheck.

    Проверки:

    npm run typecheck
    npm run lint
    npm test

    npm test запускает автотесты: проверку DTO и преобразования в Topic, обработку ошибок в transportService (fetch в тестах подменяется, к настоящему API они не обращаются) и защиту от устаревшего ответа.

    Документация кода (TypeDoc)

    У каждого файла, функции, хука, компонента, типа и поля в src есть комментарий в формате TSDoc (/** ... */). Из них TypeDoc собирает сайт с документацией:

    npm run docs

    Результат — docs/typedoc/index.html, открывается в браузере. Настройки — в typedoc.json: документируется вся папка src, кроме тестов. Включена проверка validation.notDocumented: если у чего-то нет комментария, TypeDoc выдаст предупреждение (сейчас предупреждений нет).

    Пользовательские сценарии и то, что при каждом из них вызывается в коде, — в презентации Презентация — use-case.pptx.

    Что умеет сейчас

    • Каталог с сервера. При открытии загружается весь каталог DummyJSON (194 товара). Пока идёт загрузка, виден индикатор.
    • Поиск по названию или артикулу, регистр не важен, срабатывает через 300 мс после последней буквы.
    • Фильтры: по категории (чипы, «Все» снимает фильтр) и «Только заканчивающиеся» (остаток меньше 10 штук). «Сбросить» очищает поиск и фильтры.
    • Порции: список показывается по 20 карточек, следующие 20 добавляются при прокрутке до конца или кнопкой «Показать ещё».
    • Карточка товара — отдельный экран с адресом /topic/{id}. Она сама загружает товар с сервера по id: бренд, артикул, цена, остаток, минимальная партия заказа, описание. Стрелка «Назад» в шапке или системная «Назад» возвращает к тому же списку: поиск, фильтры и место прокрутки не теряются.
    • Ссылка на товар: карточку можно открыть по прямой ссылке, даже если каталог ещё не открывали. Если истории переходов нет, в шапке кнопка «В каталог».
    • Вкладки: «Каталог» и «О приложении».
    • Ошибки адреса: неизвестный адрес — «Страница не найдена», нечисловой id — «Неверный номер товара» (без запроса к серверу), товара нет на сервере — «Товар не найден».
    • Дозаказ: кнопка «+ В дозаказ» на карточке в списке и на экране товара, счётчик внизу каталога. Отметки общие для обоих экранов.
    • Ошибки: если сервер недоступен или ответил ошибкой, показывается понятная причина, код ошибки и кнопка «Повторить».
    • Демо-режим: при ошибке можно явно включить тестовые данные. Сверху появляется плашка «Демо-данные» и ссылка «Вернуться к сети».

    Навигация

    Используется Expo Router, маршруты лежат в src/app/. Там только маршруты и layout, экраны, hooks и API — в src/features/, src/api/ и src/shared/.

    src/app/
      _layout.tsx           корневой Stack и SelectionProvider
      (tabs)/_layout.tsx    вкладки
      (tabs)/index.tsx      каталог: /
      (tabs)/about.tsx      о приложении: /about
      topic/[id].tsx        карточка: /topic/1
      +not-found.tsx        неизвестный адрес
    • Переход из каталога: router.push({ pathname: '/topic/[id]', params: { id } }). Через адрес передаётся только id, никаких объектов. Включены typed routes (experiments.typedRoutes в app.json): TypeScript проверяет, что адрес существует и id передан.
    • Карточка читает id через useLocalSearchParams и проверяет его во время работы (parseTopicId: целое число больше нуля). Тип параметра не гарантирует, что в адресе действительно число.
    • Назад: если есть история — router.back(), иначе — router.replace('/').
    • Двойное нажатие на товар не открывает две карточки: пока переход не закончился, повторные нажатия игнорируются.

    Прямая ссылка:

    Где Ссылка
    Expo Go exp://АДРЕС:8081/--/topic/1, АДРЕС — из строки Metro waiting on exp://... в терминале
    Expo Web http://localhost:8081/topic/1
    development build ostatok://topic/1 (схема ostatok в app.json)

    Проверено: Android, Expo Go ; Expo Web (Chrome), http://localhost:8081/topic/1.

    Правила хранения состояния:

    • в адресе — только id карточки и признак демо-режима ?demo=1;
    • поиск, фильтры и прокрутка — state экрана каталога. Каталог остаётся смонтированным под карточкой, поэтому при «Назад» ничего не теряется;
    • данные карточки — state useTopic, при закрытии карточки удаляются;
    • отметки для дозаказа — SelectionProvider над навигацией, общие для всех экранов;
    • после перезапуска приложения всё начинается заново, постоянного хранения нет.

    Подробные схемы — в docs/navigation.md.

    Работа с сетью

    Цепочка запроса

    CatalogScreen → useCatalog → useProductList → apiManager.products.list() → transportService.requestJson() → fetch → DummyJSON
    TopicScreen   → useTopic                    → apiManager.products.getById(id) → transportService.requestJson() → fetch → DummyJSON
    • transportService (src/shared/api/transportService.ts) — единственное место, где вызывается fetch. Здесь base URL, заголовок Accept, timeout 10 секунд, отмена через AbortController, разбор JSON, разделение ошибок и логи. React state он не трогает.
    • apiManager (src/api/apiManager.ts) объединяет тематические модули. Сейчас модуль один — products, методы list() и getById(id). В src/api/products/ лежат маршруты, тип ответа сервера ProductDto, проверка ответа (parseProduct, parseProductList) и превращение DTO в модель приложения Topic (toTopic).
    • hooks (useProductList, useTopic) вызывают apiManager, хранят состояние загрузки и превращают код ошибки в текст для пользователя.

    Проверить, что обходов нет: поиск fetch( с учётом регистра по папке src находит вызов только в transportService.ts. Без учёта регистра найдётся ещё объявление функции testFetch( в testMode.ts — это подмена для тестового режима, а не запрос.

    Base URL и timeout лежат в одном месте: src/shared/api/config.ts. Ключей и авторизации у DummyJSON нет, секретов в проекте нет.

    Ошибки

    Код Когда
    http_error сервер ответил, но со статусом не 2xx (например 404)
    network_error ответа нет совсем: нет интернета, не найден адрес
    timeout нет ответа за 10 секунд, запрос отменён
    cancel запрос отменён, потому что пользователь ушёл с экрана или начал новую загрузку. Пользователю не показывается
    parse_error ответ пришёл, но это не JSON
    contract_error JSON пришёл, но поля не те, что ожидаются (проверка DTO)

    Карточка отдельно обрабатывает 404: «Товар не найден» вместо общей ошибки.

    Стратегия поиска и порций

    Каталог загружается одним запросом GET /products?limit=0&select=... — DummyJSON отдаёт все 194 товара, ответ около 80 КБ. Поиск, фильтры и порции дальше работают локально по этому набору:

    • поиск идёт по всему каталогу DummyJSON на момент загрузки, а не по одной странице;
    • «порции» — это вывод уже загруженных данных по 20 штук, новых запросов при прокрутке нет;
    • чтобы получить свежие данные, нужно нажать «Обновить».

    Почему не серверная pagination: у DummyJSON есть limit/skip и /products/search, но поиск нельзя совместить с фильтром по категории и по остатку в одном запросе. При 194 товарах проще и честнее загрузить всё и фильтровать на телефоне. Если каталог вырастет до тысяч товаров, нужно будет перейти на серверный поиск с limit/skip.

    Отмена и гонки

    • Каждый запрос получает свой AbortController. В cleanup эффекта вызывается abort(): при закрытии карточки, смене id или новой загрузке старый запрос отменяется.
    • Дополнительно hook помнит номер последнего запроса (createRequestGuard). Ответ старого запроса не меняет данные, ошибку и индикатор, даже если он пришёл позже.
    • Во время загрузки вместо кнопки «Повторить» показан индикатор, поэтому второй такой же запрос запустить нельзя.

    Логи

    В режиме разработки каждый запрос пишет в консоль два события в JSON:

    {"event":"http.start","timestamp":"...","requestId":"mva8a7sg-2","method":"GET","route":"/products/:id"}
    {"event":"http.end","timestamp":"...","requestId":"mva8a7sg-2","method":"GET","route":"/products/:id","status":200,"outcome":"success","durationMs":140}

    requestId связывает начало и конец одного запроса, route — шаблон маршрута без query и без конкретного id, status — HTTP-статус или null, если ответа не было, outcome — итог. При ошибке проверки DTO дополнительно пишется api.contract_error с тем же requestId. В логи не попадают тела ответов, поисковые строки и заголовки. В release-сборке логи выключены (__DEV__).

    Где смотреть: логи появляются в терминале, где запущен npx expo start. Ещё можно нажать в терминале j, откроется React Native DevTools, вкладка Console. Чтобы найти один запрос, удобно вставить его requestId в фильтр консоли.

    Демо-режим и тестовый режим

    • Демо-данные (src/features/products/data/fixtures.ts, 12 товаров) включаются только кнопкой «Показать демо-данные» на экране ошибки. Пока они на экране, сверху висит плашка «Демо-данные». Тестовые данные никогда не подставляются вместо ответа сервера молча.
    • Тестовый режим сети (src/shared/api/testMode.ts) нужен, чтобы воспроизвести ошибки без отключения интернета. Он есть только в режиме разработки: панель «Тестовый режим сети» сверху каталога и карточки. Сценарии: медленный ответ 3 с, задержка 12 с, HTTP 404, нет сети, битый JSON, битый DTO. Подмена работает внутри transportService, поэтому timeout, логи и проверка ответа срабатывают по-настоящему. Когда режим включён, панель красная.

    Основная сущность называется Topic, как в методичке, но по смыслу это товар. ProductDto — то, что присылает сервер, Topic — то, с чем работает приложение. Экраны и карточки про HTTP ничего не знают.

    Metro и Hermes

    Metro — сборщик: собирает TypeScript-код проекта в один бандл и отдаёт его приложению, он же обеспечивает Fast Refresh. Hermes — движок, который выполняет этот JavaScript на телефоне. В Expo Go используется Hermes, это видно внизу списка каталога: строка «JS-движок: Hermes».
