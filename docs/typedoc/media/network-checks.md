# Проверка сетевых сценариев

Ошибки воспроизводятся через тестовый режим сети (панель сверху экрана, есть только в режиме разработки). Сценарий «Нет сети» дополнительно проверяется настоящим отключением Wi-Fi и мобильного интернета.

Платформа проверки: <!-- впиши: Android, модель телефона, Expo Go --> 

## Матрица

| Сценарий | Как воспроизвести | Ожидаемый результат | Фактический результат |
|---|---|---|---|
| Успех | Открыть приложение, открыть любую карточку | Список и карточка, `http.end` со статусом 200 | Загружено 194 товара, карточка открылась, `status: 200, outcome: success` |
| Пустой результат | Ввести в поиск `zzz` | «Ничего не найдено» и кнопка сброса | «Найдено: 0 из 194», сообщение и «Сбросить поиск и фильтры» |
| HTTP 404 | Тестовый режим «HTTP 404», нажать «Обновить» | Ошибка, `status=404`, без бесконечных повторов | «Сервер ответил, что данные не найдены (ошибка 404)», один запрос, `outcome: http_error` |
| HTTP 404 карточки | Тестовый режим «HTTP 404», открыть карточку | «Товар не найден», выход к списку | «Товар не найден», кнопка «В каталог» |
| Нет сети | Выключить Wi-Fi и мобильный интернет, нажать «Обновить» (или режим «Нет сети») | Понятная ошибка, `status=null`, доступен демо-режим | «Нет связи с сервером», `status: null, outcome: network_error`, кнопка «Показать демо-данные» |
| Timeout | Тестовый режим «Задержка 12 с», «Обновить» | Ошибка примерно через 10 с, запрос отменён | Через 10 с «Сервер не ответил за 10 секунд», `durationMs: 10001, outcome: timeout` |
| Отмена | Режим «Медленно 3 с», открыть карточку и сразу нажать стрелку «Назад» | `cancel`, экран не показывает ошибку | `outcome: cancel`, ошибки нет, список на месте |
| Гонка | Автотест `requestGuard.test.ts`: запрос A отвечает через 100 мс, AB через 10 мс | Остаётся результат AB | Тест проходит. В интерфейсе поиск локальный, поэтому гонка поисковых запросов невозможна; для списка и карточки работает тот же guard |
| Некорректный DTO | Тестовый режим «Битый DTO» (`title: null`) | `contract_error`, приложение не падает | «Сервер прислал данные в неожиданном формате», в логе `api.contract_error` |
| Невалидный JSON | Тестовый режим «Битый JSON» | `parse_error`, можно восстановиться | «Сервер прислал повреждённый ответ», после «Выкл» и «Повторить» список загрузился |
| Повтор | При ошибке нажать «Повторить» несколько раз | Одна активная попытка, затем успех | Во время загрузки кнопки нет (виден индикатор), после выключения отказа — успех |
| Порции | Прокрутить список до конца два раза | Нет дублей и лишних запросов | 20 → 40 → 60 карточек, новых запросов нет, повторов карточек нет |
| Возврат | Поиск `apple`, прокрутить, открыть карточку, вернуться | Поиск, фильтр и позиция сохранены | Запрос `APPLE`, «Найдено: 9 из 194» и место прокрутки сохранились |
| Демо-режим | При ошибке «Показать демо-данные», потом «Вернуться к сети» | Метка «Демо-данные», возврат к сети | Плашка «Демо-данные», 12 тестовых товаров, карточка без запроса; после возврата снова 194 товара |

## Логи

### Успех: открытие карточки

```
{"event":"http.start","timestamp":"2026-10-16T00:27:17.872Z","requestId":"mva8a7sg-2","method":"GET","route":"/products/:id"}
{"event":"http.end","timestamp":"2026-10-16T00:27:18.012Z","requestId":"mva8a7sg-2","method":"GET","route":"/products/:id","status":200,"outcome":"success","durationMs":140}
```

Пользователь нажал на товар, и карточка сделала один запрос за товаром по id. Обе строки относятся к одной попытке, это видно по одинаковому `requestId`. `status: 200` и `outcome: success` подтверждают, что ответ пришёл и прошёл проверку, `durationMs: 140` — запрос занял 140 мс. В `route` записан шаблон `/products/:id`, поэтому номер товара в лог не попадает.

### Управляемая ошибка: битый DTO

```
{"event":"http.start","timestamp":"2026-10-16T00:28:11.146Z","requestId":"mva8bcwa-6","method":"GET","route":"/products"}
{"event":"http.end","timestamp":"2026-10-16T00:28:11.448Z","requestId":"mva8bcwa-6","method":"GET","route":"/products","status":200,"outcome":"success","durationMs":302}
{"event":"api.contract_error","timestamp":"2026-10-16T00:28:11.449Z","requestId":"mva8bcwa-6","route":"/products","message":"Invalid field \"title\""}
```

В тестовом режиме «Битый DTO» сервер вернул 200, но у товара `title: null`. Транспорт отработал успешно (`status: 200`, `outcome: success`), а проверка в API-модуле не пропустила ответ и записала `api.contract_error` с тем же `requestId` и названием поля. Значит, сеть ни при чём: нужно смотреть DTO и mapping. На экране было «Сервер прислал данные в неожиданном формате», приложение не упало.

### Управляемая ошибка: timeout

```
{"event":"http.start","timestamp":"2026-10-16T00:28:51.182Z","requestId":"mva8c7se-8","method":"GET","route":"/products"}
{"event":"http.end","timestamp":"2026-10-16T00:29:01.183Z","requestId":"mva8c7se-8","method":"GET","route":"/products","status":null,"outcome":"timeout","durationMs":10001}
```

В режиме «Задержка 12 с» ответ не пришёл. Через 10 секунд (`durationMs: 10001`) transportService сам отменил запрос: `status: null` значит, что ответа не было вообще, `outcome: timeout` — что причина в лимите времени, а не в отсутствии сети.
