# Концепция продукта

## Название

«Остаток» (рабочее название).

## Проблема

В небольшом магазине продавец постоянно отвечает на вопросы покупателей о наличии товара. Остатки хранятся в учётной программе на компьютере, а продавец находится в зале. Чтобы ответить, он идёт к компьютеру, звонит кладовщику или отвечает наугад. Покупатель ждёт, а товар, который на самом деле есть на складе, иногда так и не продаётся.

Вторая проблема в том, что о заканчивающихся позициях узнают поздно, когда товар уже закончился.

## Идея

Мобильный справочник, где по названию за несколько секунд находится товар и видно его остаток на складе. Товары с маленьким остатком выделены, их можно отметить, и получается список на дозаказ.

## Целевая аудитория

- **Основная:** продавец-консультант. Работает в зале, телефон всегда под рукой, времени на поиск мало.
- **Дополнительная:** товаровед или управляющий. Смотрит, что заканчивается, и собирает заказ поставщику.

## Основной сценарий

Покупатель спрашивает, есть ли нужный товар. Продавец открывает «Остаток», вводит часть названия, находит товар и открывает карточку. В карточке указаны остаток в штуках, артикул и статус. Если товар есть, продавец отвечает сразу. Если осталось мало, отмечает товар для дозаказа, чтобы потом передать список товароведу.

## MVP

1. Список товаров: название, категория, остаток, картинка.
2. Поиск по названию.
3. Фильтр по категории и фильтр «только заканчивающиеся».
4. Карточка товара: описание, бренд, артикул, остаток, статус, минимальная партия заказа.
5. Отметка товаров для дозаказа и счётчик отмеченных.

## Не входит в первую версию

- изменение остатков (приход, списание, инвентаризация): выбранный API не сохраняет изменения
- вход по логину и роли сотрудников
- сканер штрихкодов
- уведомления о заканчивающихся товарах
- несколько складов и точек
- работа без интернета с синхронизацией

## Источник данных

**Основной: DummyJSON, раздел products**

- Документация: https://dummyjson.com/docs/products
- Base URL: `https://dummyjson.com`
- Доступ: HTTPS, запросы GET, ответ в JSON. Ключ и регистрация не нужны.

Нужные запросы:

| Запрос | Зачем |
|---|---|
| `GET /products?limit=10&skip=0` | список порциями |
| `GET /products/search?q=...` | поиск по названию |
| `GET /products/{id}` | карточка товара |
| `GET /products/category-list` | категории для фильтра |
| `GET /products/category/{slug}` | товары одной категории |
| параметры `sortBy`, `order` | сортировка, например по остатку |
| параметр `select` | только нужные поля |

Нужные поля: `id`, `title`, `description`, `category`, `brand`, `sku`, `stock`, `availabilityStatus`, `minimumOrderQuantity`, `price`, `thumbnail`.

Почему подходит: у товара есть готовый остаток (`stock`) и статус наличия (`availabilityStatus`, например `In Stock` или `Low Stock`). Поиск, порции и получение по id выполняются на стороне сервера, так что API закрывает все функции MVP.

Ограничения:

- данные учебные: 194 товара в 24 категориях (проверено 16.10.2026), названия на английском, цены в долларах
- запросы POST/PUT/DELETE только имитируются и ничего не сохраняют, поэтому приложение работает только на просмотр
- лимиты запросов в документации не указаны
- формат ошибки для несуществующего id в документации не описан, его нужно проверить через curl перед Sprint 4

**Резервный: Platzi Fake Store API**

- Документация: https://fakeapi.platzi.com/
- Base URL: `https://api.escuelajs.co/api/v1`
- Есть список с `offset`/`limit` и товар по id, ключ не нужен.
- Минус: нет поля с остатком, его пришлось бы хранить отдельно.

Если оба API недоступны, используются локальные тестовые данные (демо-режим), они появятся уже в Sprint 1.
