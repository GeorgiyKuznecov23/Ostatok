# Ретроспектива

## Sprint 1 — статическая витрина

**Результат.** Создан проект на Expo и TypeScript, описан тип товара `Topic`, сделана карточка `TopicCard` и экран со списком из 7 тестовых товаров. Карточка получает данные только через props, тестовые данные лежат отдельно.

**Затруднение.** Не сразу понял, как правильно перенести созданный Expo-проект в уже существующий репозиторий, чтобы не потерять историю коммитов из Sprint 0. Помогло создание проекта во временной папке и копирование без `.git`.

**Технический долг.**
- Товары выводились через `map` внутри `ScrollView`, для длинного списка это неэффективно.
- По нажатию на карточку показывается простое окно `Alert` вместо отдельного экрана.

**Что дальше.** Перейти на `FlatList` и добавить поиск, фильтры и выбор товаров.

## Sprint 2 — интерактивный локальный каталог

**Результат.** Список переведён на `FlatList`, добавлены поиск по названию и артикулу, фильтр по категории, фильтр «Только заканчивающиеся», сброс фильтров, пустое состояние и отметка товаров для дозаказа со счётчиком. Логика вынесена в hook `useCatalog`, экран только отображает данные. Долг Sprint 1 со `ScrollView` закрыт.

**Затруднение.** Отметки для дозаказа сначала хотелось хранить прямо в объектах товаров, но это была бы мутация данных. Сделал отдельный массив `selectedIds` в state и обновляю его через новый массив (`filter` и spread). Ещё пришлось разобраться, почему поиск с задержкой без cleanup срабатывал бы на каждую букву.

**Технический долг.**
- Отметки для дозаказа не сохраняются после перезапуска приложения.
- Нажатие на карточку всё ещё открывает `Alert`, а не экран товара.
- Список категорий собирается из тестовых данных, а не загружается с сервера.

**Что дальше.** По порядку курса следующей идёт работа с сетью (Sprint 4): загрузка товаров из DummyJSON с состояниями загрузки и ошибки. Затем навигация (Sprint 3): отдельный экран карточки товара вместо `Alert`.

## Sprint 4 — сетевой каталог

**Результат.** Каталог загружается из DummyJSON, карточка товара загружается по id. Запросы идут по цепочке hook → apiManager → transportService → сеть, `fetch` есть только в transportService. Ответ сервера проверяется до использования. Есть timeout, отмена, повтор, демо-режим, логи с requestId и автотесты. Долги Sprint 2 по `Alert` и категориям из тестовых данных закрыты.

**Затруднение.** Больше всего времени ушло на то, чтобы правильно отличать ошибки. Сначала казалось, что любой неудачный запрос попадает в `catch`, но `fetch` с ответом 404 завершается успешно, и статус нужно проверять самому через `response.ok`. Ещё пришлось разобраться, как отличить timeout от отмены: оба делают `abort()`, поэтому для timeout стоит отдельный флаг.

**Технический долг.**
- Каталог грузится целиком. Для 194 товаров это нормально, для тысяч нужен серверный поиск с `limit/skip`.
- Карточка — окно поверх списка, на неё нельзя дать ссылку.
- Отметки для дозаказа по-прежнему пропадают после перезапуска.
- Нет кэша: после перезапуска список загружается заново.

**Что дальше.** Sprint 3 — навигация на Expo Router: отдельный экран карточки `topic/[id]`, вкладки, открытие карточки по прямой ссылке.

## Sprint 3 — навигация сетевого справочника

**Результат.** Приложение переведено на Expo Router: вкладки «Каталог» и «О приложении», карточка `/topic/[id]` в корневом Stack, экран для неизвестного адреса. Карточка открывается по прямой ссылке, сама загружает товар и проверяет id из адреса. Возврат сохраняет поиск, фильтры и прокрутку. Долг Sprint 4 «на карточку нельзя дать ссылку» закрыт.

**Затруднение.** При открытии карточки по прямой ссылке приложение падало с ошибкой «The imperative router is unavailable before the first render». Оказалось, что `router.canGoBack()` нельзя вызывать во время первой отрисовки. Заменил на `useNavigation().canGoBack()`. Второе: после переноса карточки на отдельный экран отметки «В дозаказ» из карточки перестали попадать в каталог, потому что у каждого экрана свой state. Вынес отметки в Provider над навигацией.

**Технический долг.**
- Фильтры каталога не попадают в адрес, ссылкой на отфильтрованный список поделиться нельзя.
- Отметки для дозаказа по-прежнему пропадают после перезапуска.
- Каталог по-прежнему грузится целиком.

**Что дальше.** Сохранять отметки для дозаказа между запусками и передавать список товароведу.
